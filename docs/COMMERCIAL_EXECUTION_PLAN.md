# StudyCheck Commercial Execution Plan

## Current position

P1 core learning functionality is substantially implemented and P3 HTTP foundations exist, but P1 is not declared PASS until the complete real-document learning loop is executed successfully. AI provider code is groundwork only and does not constitute a P2 PASS.

## Remaining execution rounds

1. **P1 Gate** — real TXT/PDF/DOCX ingestion, knowledge extraction, practice generation, answer submission, mastery update, wrong-answer/review scheduling and progress verification.
2. **P2 Learning intelligence** — provider abstraction, structured generation, source grounding, output validation, difficulty and explanation quality, timeout/retry and deterministic fallback.
3. **P3 Product API/Web** — authenticated material/plan/practice/answer/review/progress workflow, user isolation, persistent task state and usable web UX.
4. **P4 Monetization** — free quota, Pro entitlement, usage metering, subscription/order abstraction and payment boundary.
5. **P5 Production** — PostgreSQL migration path, object storage, background jobs, observability, rate limiting, security hardening, Docker deployment and operational docs.
6. **P6 Commercial MVP + final gate** — landing page, onboarding, sample content, learning dashboard, pricing, trial/paid path, reports/help and production smoke test.

## Completion rule

The product is complete when a new user can register, upload real study material, complete knowledge-point → practice → answer → mastery → wrong-answer → review, see measurable progress and understand how to pay. Non-blocking enhancements become backlog after each gate.
